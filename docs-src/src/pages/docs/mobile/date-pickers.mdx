A date picker collects a date, a time, or both. On touch it is a month grid with cells big enough to hit, opened from a button showing the current value.

## When to use it

Use a date picker when the answer is a real date and the surrounding dates matter: choosing a day to travel, booking a slot, setting a deadline.

Use a plain <a href={`${import.meta.env.BASE_URL}docs/mobile/forms/`}>text field</a> with `type="date"` when you only need the value and the platform's own picker is good enough, which is often. A native picker is one line of markup and works everywhere.

## The value button

iOS does not show a calendar inline. It shows the current value as a quiet capsule, and opens the calendar when that is tapped.

| Part | Value |
|---|---|
| Panel | 370px wide, 13px radius, 16px padding |
| Day cell | 44 x 44px, full circle |
| Grid | 49px column pitch, 51px row pitch |
| Day number | 20px, weight 400, tracking -0.45px |
| Weekday header | 13px, weight 590, uppercase, at 30% |
| Month title | 17px, weight 590, tracking -0.43px |
| Today | Accent number, no fill |
| Selected | Filled accent circle, white number |
| Outside month | 30% |

The day cell is 44px, so the calendar is the one place where the grid and the tap target are the same thing. That is also why the panel is 370px: seven 44px cells plus padding is what a phone width allows.

The cells are spread with `space-between` rather than dropped into seven equal columns, so the first and last circle in a row sit flush against the panel's padding. At 370px that works out to 5px between cells horizontally and 7px vertically.

Today and selected are two different marks. Today is the accent as a number. Selected is the accent as a filled circle. A day can be both, and the fill wins.

The grid is driven by `datepickers.js`, the same script the pointer calendar uses.

```html
<script type="module" src="/js/datepickers.js"></script>
```

## Dark mode

Numbers flip from black to white, the accent from `#0088FF` to `#0091FF`, and the weekday headers and outside-month days stay at 30% against the light values.

## Accessibility

Day cells are buttons in a grid. Give the selected one `aria-selected="true"`, which drives the visual state as well.

Weekday headers are abbreviations, so spell them out for assistive tech rather than leaving "SUN" to be guessed at.

Focus draws a 3px accent ring inset into the cell, matching the circle.

A calendar is a lot of controls. Always offer a text alternative for the same value, so people who do not want to navigate 30 buttons can type a date instead.

## The macOS calendar

`pickers.css` ships both. `.p-calendar` alone is the macOS graphical picker: 11px numbers on an 18px pitch with a 16px pill, sized for a pointer. Adding `.p-calendar-touch` swaps it to iOS metrics.

Two rules have to be cleared rather than overridden when it does: macOS marks today with a gray pill background, and its day cells take a hover fill. iOS marks today with the accent number alone, and touch has no hover.

The analog clock in the same file is macOS-only and still experimental.
