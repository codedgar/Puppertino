Ask an agent for "a web settings page that feels like a Mac app" and you get a guess. Tailwind-gray cards, a 16px body, a blue that is almost Apple's, no dark mode, no focus rings. The agent has seen a lot of Apple screenshots and none of the rules behind them.

The Puppertino skill gives it the rules and the markup. It ships inside the Puppertino repository, as a plain `SKILL.md` with two reference files, so the recipes change in the same commit as the framework.

## Install

With the `skills` installer:

```bash
npx skills add codedgar/Puppertino
```

In Claude Code, as a plugin:

```bash
claude plugin marketplace add codedgar/Puppertino
claude plugin install puppertino@puppertino
```

Or copy `skills/puppertino` into your skills folder. The [Agent skill](/docs/agent-skill/) page has the long version.

## What the agent learns

Three things, in the order it needs them.

**When to use it.** Mac-style or iPhone-style interfaces on the web, Apple-style settings pages, dashboards, Electron and Tauri apps, PWAs, Liquid Glass, Apple system colors, Apple's type scale, or any project that already loads Puppertino. It also knows what stays out of the output: the Apple logo, Apple trademarks as a product name, SF Pro font files, Apple's icons and artwork, and any claim of Apple's endorsement. Ask for a full desktop in a browser tab and it builds one, with a single note that the framework is tuned for products rather than system clones.

**The rules.** Apple's text styles with sizes, weights and tracking. Thirteen system accents with their light and dark values. The 4px spacing grid. Corner radii per element. Five material thicknesses. Four shadow levels. Motion timings and the spring curves. The accessibility floor: 4.5:1 contrast, 44px targets, a focus ring that never disappears. All of it condensed in `references/hig.md`.

**The markup.** A macOS window with a sidebar and toolbar. A settings form with fields, a select, a switch and a segmented control. Lists and tables. An alert with a destructive action. An iOS screen with a navigation bar, an inset list and a tab bar. Touch buttons and fields. Liquid Glass switches and sliders. Materials. Scoped dark mode. Each one is real Puppertino markup in `references/recipes.md`, and for anything else the agent fetches [llms-full.txt](/llms-full.txt), which lists every class in every stylesheet.

Every color is a `--p-` token, so the same markup is correct in dark mode. The switch is a checkbox and the segmented control is a radio group, so forms, labels and keyboard navigation work without a script.

## Why a skill and not a prompt

A prompt is written once and forgotten. A skill is a file in the repository, versioned with the framework, and loaded only when the task matches its description. When a component changes, the recipe changes in the same commit, and the next agent that loads the skill gets the current markup.

The skill also carries the checks a reviewer would run: one prominent button per view, red only for destructive actions, 44px targets on touch, an opaque fallback under every blur, and nothing of Apple's in the output.

## A prompt to try

> Build the account settings page for a Mac companion app. Sidebar on the left with General, Notifications and Privacy. The General pane has name, email, a sync switch and a List or Grid segmented control. One Save button.

The agent picks the desktop set, loads one stylesheet, writes the sidebar, the form and the buttons from the recipes, uses tokens for every color, and checks dark mode and focus before it answers.
